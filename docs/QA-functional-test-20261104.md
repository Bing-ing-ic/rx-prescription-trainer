# 医学生处方推演训练平台 · 全面功能测试报告

- 测试时间：2026-11-04
- 测试对象：线上版 https://bing-ing-ic.github.io/rx-prescription-trainer/ （与本地 D:\医学生处方推演训练平台 同源）
- 测试方式：静态代码走查（index.html / app.js 1908行 / rule-engine.js 713行 / review.js / admin.html / login.html / 4个JSON数据文件）+ 浏览器实测全流程
- 数据规模：46 个病例、318 个药品、36 条规则

---

## 一、总体结论

平台主流程可跑通（随机病例 → 三级诊断提示 → 双通道处方 → 规则点评 → 报告 → localStorage 画像/错题/统计），首页、药品库、能力画像、错题本、学习统计、登录页、管理后台均能正常打开与渲染。

但**规则引擎与前端之间存在多处"断链"**：设计文档里的关键教学规则（皮试核查 IV-08、输液指征 IV-01 error 级、同瓶配伍 drug_drug、跨通道 DUP-02）在真实 UI 流程中要么无法触发、要么误报。另有 **1 个严重作弊级漏洞（空处方得 100 分）**。

严重程度统计：**高 5 个 / 中 9 个 / 低 8 个**。

## 三、Bug 清单

### 🔴 高级

**B-01 空处方（零药品）提交可得 100 分"优秀"**
- 复现：新病例 → 确认诊断 → 选非输液处方 → 不加任何药 → 直接点"提交点评"。
- 预期：阻断提交，或至少报"未开具任何药品"error。
- 实际：满分通过，报告仅在"参考对比"里灰字提示"缺少首选用药"，**不扣分**。实测慢性湿疹病例空处方=100分。学生可以完全不开药刷高分。
- 位置：app.js `submitRx()`（约1281行）对 normal 通道无任何 items 非空校验。

**B-02 皮试结果无法录入，需皮试药品 100% 误报 IV-08 error**
- 复现：任意肺炎类病例 → 输液通道 → 选 0.9%NS → 添加"注射用头孢呋辛钠"（skin_test_required=true）→ 提交。
- 预期：UI 提供皮试阴性/阳性选择；阴性则 IV-08 pass。
- 实际：输液组表格只有 序号/类型/药名/规格/单次剂量/途径/频次/数量/滴速/删除，**没有皮试列**；提交时代码把每组硬编码 `skin_test_required:false, skin_test_result:'not_required'`（app.js 约1311行），而规则引擎按 `drug.skin_test_required=true` 检测 item 上无 `skin_test_result` → 必报 error"需皮试但未填写"，学生无处补救。实测头孢呋辛钠输液处方被误判 error。
- 影响：11 个需皮试药品（阿莫西林、各头孢、青霉素类）在输液通道一律误报；README 用例B"皮试阴性100分"在真实 UI 无法复现。口服阿莫西林胶囊（同样需皮试）则因 IV-08 只在输液块内运行而**完全不查**，双向都错。

**B-03 输液指征 IV-01 被硬编码理由降级，error 级规则形同虚设**
- 复现：普通感冒（usually_no_iv + 负面清单）→ 选输液 → 提交。
- 预期：无指征输液应触发 IV-01 **error**（设计：fever/other 等弱指征→error）。
- 实际：app.js 提交时把 iv_reason 写死为 `'student_selected_iv'`（约1321行），该值不在引擎的"弱指征"列表里 → 落入 else 分支只报 **warn**；IV-02 也随之变 pass。实测报告 IV-01 为 warn。整个"能口服不输液"的核心教学处罚被削弱一档，且 UI 根本没有 iv_reason 下拉（index.html 注释自称"选输液即视为有指征"）。

**B-04 多组输液时 IV-07 中药注射剂"同瓶混合"误报**
- 复现：组1 = NS + 清开灵注射液（单独），组2 = NS + 头孢呋辛钠（正确分瓶）→ 提交。
- 预期：中药注射剂单独成组 → IV-07 pass。
- 实际：规则引擎在拍平后的全局 `iv.items` 上判断"同瓶"（rule-engine.js 486-494行），完全不看 `ctx.groups` 分组 → 分瓶也报 error"同瓶混合"。引擎拿不到分组信息。

**B-05 compat.json 的 drug_drug 同瓶配伍规则完全未接入引擎**
- 现状：compat.json 维护了 6 条 drug_drug 规则（如 头孢呋辛钠+维生素C 同瓶禁忌、泮托拉唑+VC pH 不相容）和 tcm_injection_rules（清开灵须 10%GS）。
- 实际：rule-engine.js 只读 `compat.solvent_drug`，**全文未出现 `compat.drug_drug` / `compat.tcm_injection_rules`**。学生把头孢呋辛+维生素C混在同一瓶，引擎不报。数据白建。

### 🟡 中级

**B-06 药品分类（pharmacology_class）体系混乱，DUP-01 同类重复用药大面积失效**
- 现状：318 个药落到约 105 个 class，大量同义重复：ACEI/…、CCB/钙通道阻滞剂（CCB）、nsaid/NSAIDs/COX-2抑制剂/cox2_inhibitor、PPI/质子泵抑制剂（PPI）、quinolone/喹诺酮类、macrolide/大环内酯类、statin/他汀类/他汀类调脂、cephalosporin_2/二代头孢/一代头孢、biguanide/双胍类降糖药、beta_blocker/β受体阻滞剂……
- 影响：同开"阿托伐他汀(statin)+瑞舒伐他汀(他汀类)"、两种 NSAID 不同类名，DUP-01 均不判重复；药品库分类下拉也因此变成中英文混杂长列表。

**B-07 溶媒用量在 UI 修改后，提交仍按原始规格名做配伍匹配**
- 复现：选 0.9%NS 100ml/袋，把单次用量改成 250ml → 提交。
- 实际：提交时 `solvent_name = g.solvent.generic_name + ' ' + g.solvent.spec`（约1304行），spec 仍是"100ml/袋"，不随修改后的 volume_ml 更新；compatible/incompatible 判断、allowed_solvents 匹配都用了陈旧名称。

**B-08 多组输液只取第一组的滴速/总量做规则判断**
- 现状：ivCtx.drip_speed_mlh / total_volume_ml 全部取 `groupDetails[0]`（约1326-1327行）。第二组及以后的滴速过快、超量，POP-02/IV-04 都发现不了。

**B-09 次要诊断（合并症）录入后不参与任何规则判断**
- 现状：次要诊断框可输入、有联想、报告里灰字提示"请确认合并症用药"，但 ctx 里根本不带该字段；开降压药仍按主诊断查 YN-02，合并症用药漏治/误治都不触发。功能半成品。

**B-10 SPEC-02 禁忌症识别为死规则**
- 现状：患者标志 pregnancy/glaucoma/pepticUlcer/renalArteryStenosis 全部从 `patient.note` 正则推断，而 newCase 从不生成 patient.note；patient.hepatic_insufficiency、heart_renal_insufficiency 也从不赋值（硬编码 false）。SPEC-02、DOSE-02 肝分支、儿童体重必填分支在真实流程中永不触发。

**B-11 DUP-02 跨通道同类重复不可达**
- 现状：UI 一次就诊只能选口服或输液其一；选输液时 normal_rx 被塞成空 items 占位。collectRoutes 永远拿不到同时存在的口服+静脉药。README 已列为已知限制，但引擎代码与"双通道同次就诊"教学目标脱节。

**B-12 普通感冒诊断方向提示文案自相矛盾**
- 实测：错两次后提示"本病例无发热、无咽痛、无咳嗽——不是呼吸道感染"，而本病例恰恰就是呼吸道感染。该 HINT 字典条目把"鉴别排除话术"挂到了本病种自己身上，会把学生带偏。

**B-13 CountAPI 已死亡，后台"全站访问次数"永久加载失败**
- 实测控制台：`api.countapi.xyz` 全部 `ERR_NAME_NOT_RESOLVED`，且 index.html 第423行 fetch 无 .catch，每次加载抛 Uncaught (in promise) TypeError。后台该卡片永远"加载中…"。建议移除或换统计方案。

**B-14 口服药数量反推疗程的单位换算错误**
- app.js n-qty onchange（约1000行）用 `parseFloat(it.single_dose)` 直接乘除：single_dose 是"0.5g"时 parseFloat=0.5，与按片数计算的 spec.amount（0.25）量纲混淆，反推出的疗程天数明显不对（n-days 改天数反推片数同理）。

### 🟢 低级

**B-15** FMT-06 输液编号校验是死代码：前端生成的输液编号一律 `IV-JCK-/IV-ET-` 开头，永远不会触发该 warn。
**B-16** 所有患者身份证号硬编码相同（`5301**********0011`）。
**B-17** restricted 级职称确认全局化：一次确认后整会话不再询问；且不随新病例重置外的任何时机复核。
**B-18** localStorage 读取（renderRadar/renderStats/renderMistakes/saveHistory）均无 try/catch，历史数据一旦损坏（如手动改错JSON）整页脚本中断。
**B-19** 3 个溶媒（甘露醇、5%葡萄糖氯化钠500ml、10%GS500ml）在 drugs.json 里 `volume_ml` 为空，autoFillGroup 兜底成 100ml，输液表用量格显示空"ml"。
**B-20** admin 后台纯前端 sessionStorage 校验、默认密码 admin123 公开在源码里（教学用途可接受，但应在交付物中明示"非真实安全"）。
**B-21** 报告页注释"评分器各维度权重合计为105"为过时注释，实际合计100。
**B-22** 病例卡生命体征展示的是区间原始值（"T 37.3-37.8℃"），与患者真实采样值不一致（采样值只在报告页出现），两处口径不统一。

## 四、缺失功能清单

1. **输液指征（iv_reason）选择 UI**：发热/脱水/不能进食/序贯治疗等下拉缺失，导致 IV-01/IV-02 的分级教学路径不可达。
2. **皮试结果录入 UI**：需皮试药品（11种）无阴性/阳性选择控件。
3. **过敏史/既往史表单**：青霉素过敏、妊娠、青光眼等 SPEC-02 触发前提不存在。
4. **同次就诊双通道流程**（先口服后静脉序贯）：DUP-02 无 UI 入口。
5. **drug_drug 同瓶配伍规则**接入引擎（数据已备）。
6. **多组输液逐组滴速/总量判断**与逐组皮试。
7. **空处方/未诊断提交的硬阻断**。
8. **数据导出后的导入/恢复**功能（admin 只能导出不能导入）。
9. 儿科淡绿、麻精淡红处方笺的入口切换（CSS 已就绪，README 已列）。
10. 诊断库泛化：DESCRIPTION 模糊匹配仍依赖子串重合，无纠错（README 已列）。

## 五、按优先级的修复建议

1. **P0（本周）**：B-01 空处方提交阻断；B-02 补皮试录入 UI 并让提交时携带 `skin_test_result`；B-03 iv_reason 改回真实下拉或修正弱指征判定（至少把 `student_selected_iv` 视为弱指征）。
2. **P1**：B-04/B-05 让引擎按 `ctx.groups` 做同瓶判断并接入 drug_drug；B-06 统一药品分类词表；B-07/B-08 多组输液参数传递。
3. **P2**：B-09 次要诊断接入 YN-02；B-10 生成患者合并症标志；B-13 下线 CountAPI；B-12 修正感冒提示文案；B-14 修正数量-疗程反推。
4. **P3**：低级项统一清理（死规则、硬编码身份证、容错、注释）。
